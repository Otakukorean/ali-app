# الغيث (Alghaif)

A Flutter Windows desktop application, Arabic-only (RTL), backed by a local SQLite database. It provides role-based login (admin / super admin), a sites browser, a per-site number-range picker, admin user management, and a "Constants" directory page.

## Features

- **Login** — Arabic RTL UI, username/password, authenticated against a local SQLite database.
- **Roles** — `admin` and `superadmin`. A default super admin is seeded automatically the first time the app runs.
- **Home** — three sections: المشرفين (Admins, super admin only), المواقع (Sites), الثوابت (Constants).
- **Admins** — full CRUD (list, add, edit, delete) for admin accounts, including a profile photo.
- **Sites → Numbers** — each site (الكرار، الأمين، المفيد) has one or more number prefixes (e.g. `111`, `113`, `100`, `115`). Tapping a prefix card opens a sheet listing all 100 numbers in that range (e.g. `11100`–`11199`).
- **Constants** — a header card with fixed IP / WhatsApp / landline info, plus a table of entries (name, phone, IP, photo) you can add to.

## Prerequisites

1. **Flutter SDK** (stable channel) — [install guide](https://docs.flutter.dev/get-started/install/windows).
   Add `<flutter-install-dir>\bin` to your `PATH`.
2. **Visual Studio 2022** with the **"Desktop development with C++"** workload — required to build the native Windows runner. Install via the [Visual Studio downloads page](https://visualstudio.microsoft.com/downloads/).
3. Enable Windows desktop support once per machine:
   ```bash
   flutter config --enable-windows-desktop
   ```
4. Verify your setup:
   ```bash
   flutter doctor
   ```
   You should see a check mark next to "Visual Studio" and "Windows (desktop)" should appear as a connected device.

## Installation

```bash
git clone https://github.com/Otakukorean/ali-app.git
cd ali-app
flutter pub get
```

## Running (development)

Runs the app in debug mode with hot reload:

```bash
flutter run -d windows
```

## Building a release executable

```bash
flutter build windows
```

The output executable and its required DLLs are placed in:

```
build\windows\x64\runner\Release\alghaif.exe
```

You can copy that entire `Release` folder to another Windows machine and run `alghaif.exe` directly — no Flutter SDK is required on the target machine.

## First run / default login

On first launch, if the local database has no users yet, a default super admin account is created automatically:

| Field | Value |
|---|---|
| Username | `superadmin` |
| Password | `admin123` |

**Change this password after first login** (there is currently no in-app "change my own password" screen — a super admin can edit any admin account's password from the المشرفين screen, but to change the super admin's own credentials you would need to edit the database directly, or ask for that screen to be added).

## Data storage

The app uses `sqflite_common_ffi` (SQLite via FFI, no native platform-channel plugin needed on Windows). The database file and any uploaded images (admin avatars, constants-entry photos) are stored under the OS "Application Support" directory for this app, typically:

```
%APPDATA%\alghaif\alghaif.db
%APPDATA%\alghaif\avatars\
%APPDATA%\alghaif\images\
```

Deleting the `alghaif` folder there resets the app to a fresh install (a new super admin will be re-seeded on next launch).

## Project structure

```
lib/
  core/
    db/            Database helper: schema creation + versioned migrations
    security/       Password hashing (SHA-256 + per-user salt)
    storage/        Shared helper for copying picked images into app storage
    theme/          App-wide colors/typography
  models/           Plain data classes (AppUser, Site, SitePrefix, ConstantsEntry, ...)
  services/         Data-access layer (AuthService, SiteService, UserService, ConstantsService)
  screens/          UI screens (login, home, sites, numbers, admins, constants, ...)
  app.dart          MaterialApp setup (Arabic locale, theme, initial route)
  main.dart         Entry point; initializes sqflite_common_ffi and the database
windows/            Native Windows runner (generated by `flutter create`, customized for UTF-8 window title)
test/               Widget tests
```

## Known limitations / possible follow-ups

- No in-app screen to change the super admin's own password.
- No edit/delete UI for site prefixes or constants-entry rows beyond delete (site prefixes are seeded in code; constants entries support add + delete, no edit).
- No password-reset flow.
